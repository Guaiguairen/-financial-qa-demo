## 二、两处关键工程决策

**1. 解析档位选择（basic vs flash 实测对比）**：同一页表格 HTML 在两档下逐字节一致（对带文本层的电子版 PDF，两档共用原生版式解析路径）；basic 标题标注更细但本机 6GB 显存下性能波动严重（版面推理 0.08s/页 → 120s/页），flash 稳定约 4 页/秒。**结论：flash 档全量解析**，并以评测检验表格质量无损。

**2. 答案引擎与证据预算**：生成从本地 Qwen3-1.7B 切换为 DeepSeek API 后（详见第三节的版本对比），上下文与推理能力大幅提升，同时项目体积减少约 4GB；证据预算从"显存硬约束"（≤10 块/3000 字）放宽为"成本与信噪比软约束"（≤16 块/12000 字）。

## 三、评测分析：成绩从哪里来，问题在哪里

**最终成绩：9 题完全正确 + 1 题部分正确（q09）。** 单公司事实题 8/8；跨公司全景题 1 全对（q10）+ 1 部分（q09）。

**这 10 分不是一步到位的，四个版本的迭代是本次作业最有价值的工程记录：**

| 版本 | 关键变化 | 成绩 | 暴露/修复的问题 |
|---|---|---|---|
| v1 | 本地 Qwen3-1.7B | 4/10 | 密集表格数字与单位误读（海光研发投入）；母公司/合并口径混淆（龙芯净利）；期间错配（取 Q4 当全年）；全景题实体绑定混乱 |
| v2 | 切换 DeepSeek API | 7/10 | 数字、单位、口径类失败基本修复；剩余问题指向检索侧 |
| v3 | **修复嵌入池化缺陷** | 9/10 | **发现 61% 的向量因左填充池化错误而退化为同一向量**（短文本取到填充位）；按官方池化方式修复并重建索引后，此前"检索漏召"的 q04/q08 关键块直接跃升 Top1——这条 bug 一直是多道题翻车的真正根源 |
| v4 | 检索终调（干扰抑制 + 召回窗口） | 9✓+1⭕ | 点名公司时抑制他家噪声、双指标题扩大召回窗口 |

**答得好的一类**：所有指向"管理层讨论叙述句 + 结构表"的单公司事实题（8/8），以及研发强度全景题（q10，靠"公司均衡召回"让 8 家公司同场出现）。答案具备精确数字、单位、口径标注与可溯源引用。

**唯一翻车（q09，多公司对比）及其原因**：四家公司的对比中，澜起与瑞芯微的**全年**数据块在全局排序中位置靠后（多公司块相互挤占），未进入证据窗口；模型基于可得证据给出正确结论（寒武纪增速最高）并诚实标注缺失。这是"单轮证据容量 vs 多公司覆盖"的结构性矛盾，也是下一步最值得投入的方向（见下节）。

## 四、已知局限与改进方向

1. **多公司对比的两段式流程**：按公司分组检索与抽取 → 再合并对比（map-reduce），解决 q09 类覆盖缺口；
2. **表格三元组化**：将关键表格行预处理为（项目，数值，单位）再入证据，进一步提升数字题精度下限；
3. **外部依赖说明**：生成依赖 DeepSeek API（需网络与 Key，成本约每题 <0.01 元）；检索与嵌入（Qwen3-Embedding + BM25）完全本地运行；
4. **PDF 源瑕疵**：个别表格在源文件中存在字符错序（如数字呈现为"632,,.225584"），两种解析档位均无法修复，评测已回避此类考点。
